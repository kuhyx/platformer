# Parameter registry contract

Single source: `shared/params/params.json`. Per-prototype copies are
generated by `make gen-params`; never edit a copy.

## Entry shape
```json
"jump_velocity": {
  "value": 420, "min": 100, "max": 1000, "step": 10,
  "unit": "px/s", "desc": "Initial upward speed on jump"
}
```
- `value` is the shipped default. `min`/`max` bound the debug slider.
  `step` is the slider increment.
- All numbers. Booleans as 0/1. Strings are not tunables.
- Keys are snake_case and unique across the whole game.
- Keys starting with `_` are metadata, not tunables; loaders skip them.

## Rules
1. Code reads tunables through the engine's accessor
   (`Params.get_value("jump_velocity")`, `param("jump_velocity")`,
   `PARAM(P_JUMP_VELOCITY)`, …). No literal copies.
2. Adding a tunable: add the entry, `make gen-params`, use it. Nothing else.
3. Removing a tunable: delete the entry. A lint or compile error in a
   prototype is the intended signal.
4. Debug overlays are generated from the registry, never hand-built.
5. The registry file's hash is stored in every save, replay and
   analytics session.

## Generated targets
| Prototype | File | Form |
|---|---|---|
| godot, phaser, bevy | `params.json` | copy with `_generated` marker |
| love | `params.lua` | Lua table, same fields |
| raylib | `params.h` | `PARAMS[]` table + `P_*` enum + `PARAM()` macro |

## Validation
`python3 tools/validate_params.py` fails when a key lacks a field,
`value` is outside `[min, max]`, or `step` ≤ 0.

## Non-tunables
Fixed by decision, not slider: sim tick (60 Hz, D12), internal resolution
(854×480, D13), input map (D05). Changing these is a new decision.
